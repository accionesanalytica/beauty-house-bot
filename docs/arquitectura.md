# Arquitectura Shoow — versión texto

Chat de WhatsApp (cliente le escribe a Isa) → API de Meta / WhatsApp Business API (la puerta de entrada oficial que recibe el mensaje y permite responder; requiere el negocio verificado en Meta Business Manager) → Bot / orquestador (el cerebro: decide si es una FAQ, un pedido nuevo, o algo que necesita escalarse a Isa; acá vive la lógica de negocio) → Base de conocimiento de FAQs (documento con las respuestas ya relevadas — horarios, envíos, cambios/devoluciones, talles — el bot lo usa como referencia para contestar sin inventar) → API de Tiendanube (donde el bot consulta stock real y crea el pedido, una vez que el cliente confirma qué quiere) → Aprobación manual de Isa (en el MVP, toda operación espera el OK de Isa antes de procesarse — vía su propio hilo de WhatsApp con el bot, separado del de clientes) → Generación de etiqueta de envío (si el transportista es Correo Argentino o Andreani, Tiendanube ya la genera nativa vía Envío Nube — sin RPA; si es un transportista sin integración tipo Siempre Logística, ahí entraría el RPA) → Entrega al cliente (retiro en persona, envío a domicilio, o excepción manual tipo Uber para casos urgentes/VIP, resuelta por Isa fuera del sistema).

En paralelo: Sincronizador de stock (corre cada 12 horas, cruza lo que hay realmente disponible entre Tiendanube y la operación física de Isa — resuelve el problema de fondo de que hoy el stock no se actualiza solo).

**Nota sobre Postgres (corregido 2026-08-04):** Postgres no guarda pedidos como registro definitivo — Tiendanube es siempre la única fuente de verdad de pedidos y stock. Postgres solo guarda estado de conversación, la cola de pedidos en borrador pendientes de aprobación de Isa, y el log de mensajes. El pedido "nace" recién cuando Isa aprueba y el bot lo crea en Tiendanube vía API.

Isa habla con la IA (hilo de WhatsApp separado, exclusivo para ella) → Bot / orquestador (mismo cerebro de arriba, pero en modo "consulta/corrección" en vez de modo "atención a cliente") → puede preguntar estado de pedidos, corregir stock, aprobar operaciones pendientes.
